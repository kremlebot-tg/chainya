# Checkout backend

Сервер сам считает цены по `../telegram-bot/teas.json`, сохраняет заказы в
SQLite и подключает Т-Банк, CDEK, Saby и Telegram. Тестовая оплата
регистрируется только при явном `CHAINYA_TEST_MODE=1`; в production её маршрутов
нет.

```bash
cd /Users/mac/Documents/Сайты/Чайня/site
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
python3 build.py --web
CHAINYA_TEST_MODE=1 .venv/bin/uvicorn backend.app:app --reload --port 8080
```

Открыть `http://127.0.0.1:8080`. База создаётся в `backend/data/` и не попадает
в Git.

## API

- `GET /api/health` — состояние и число позиций каталога.
- `POST /api/delivery/quote` — актуальный расчёт доставки СДЭК по корзине и городу.
- `POST /api/orders` — серверная проверка, расчёт и сохранение заказа.
- `GET /api/orders/{id}` — состояние заказа.
- `POST /api/orders/{id}/test-pay` — имитация webhook успешной оплаты, только
  при `CHAINYA_TEST_MODE=1`.
- `POST /api/analytics/events` — обезличенное событие сайта без IP, cookies и user-agent.
- `GET /api/admin/dashboard?days=30` — агрегаты, графики, воронка и состояние систем.
- `GET /api/admin/orders?q=&status=&limit=50&offset=0` — поиск и постраничная очередь заказов.
- `GET /api/admin/business-leads?q=&status=&limit=50&offset=0` — поиск и постраничные B2B-заявки.
- `GET /api/admin/saby/status` — готовность конфигурации Saby без раскрытия секретов.
- `POST /api/admin/saby/test` — проверка авторизации и получение точек продаж.
- `GET /api/admin/saby/catalog-preview` — первые 25 позиций выбранного прайс-листа.
- `GET /api/admin/integrations/status` — сетево-независимая готовность Т-Банка, Saby и CDEK.
- `GET /api/admin/orders/{id}/integration-preview?ready_at=YYYY-MM-DD HH:MM:SS` —
  предварительные входные данные интеграций без внешних запросов и записей.

В production стоимость и доступность доставки рассчитываются через CDEK API,
а платежи создаются через Т‑Банк. Mock-оплата существует только при явном
`CHAINYA_TEST_MODE=1` и недоступна на production-vhost. Секреты передаются
только через защищённые переменные окружения.

Подготовительные адаптеры находятся в `tbank.py`, `cdek.py` и `saby_sync.py`.
Они ничего не запускают при импорте. Все будущие внешние записи обязаны идти
через `IntegrationWriter`: единый guard запрещает их в `CHAINYA_TEST_MODE`, при
неопубликованном workflow и в режимах `off`/`shadow`. Только точное значение
`CHAINYA_TEST_MODE=0` отключает тестовый предохранитель; опечатки остаются в
безопасном тестовом режиме.

Панель владельца открывается по `/manage`. Ключ вводится на отдельной странице
входа и проверяется сервером. После успешной проверки сервер выдаёт
`HttpOnly; Secure; SameSite=Strict` cookie на 12 часов; сырой ключ не хранится
в JavaScript и браузерном хранилище. Старые ссылки `/manage#ADMIN_TOKEN` и
`/admin/orders#ADMIN_TOKEN` остаются переходным способом входа: минимальная
страница отправляет ключ серверу, сразу удаляет fragment из адреса и получает
ту же защищённую сессию. Без сессии полноценная HTML-оболочка панели не
выдаётся. Выход выполняется кнопкой в правом верхнем углу.

Сырые события статистики хранятся не более 360 дней.

Если заданы `BOT_TOKEN` и `OWNER_CHAT_ID`, после первого перехода заказа в
`paid` backend отправляет владельцам уведомление через Telegram. Повторный вызов
эндпоинта оплаты не дублирует сообщение.

## Saby Retail

Клиент `backend/saby.py` уже поддерживает сервисную авторизацию, точки продаж,
прайс-листы, каталог с ценами и остатками, компании, склады и создание заказа на
доставку. Сервисное приложение, точка 274 и прайс-лист 7 настроены; dry-run
сверяет 31 стабильный `externalId`. Внешняя запись всё равно выключена: точка
ещё не подключена к продукту `delivery`, а одна активная позиция сайта имеет
нулевой остаток в Saby.

Скопируйте значения из `backend/saby.env.example` в защищённый серверный файл
`/etc/chainya-shop-saby.env`. После добавления трёх ключей в админ-панели станет
доступна кнопка проверки подключения. После выбора точки и прайс-листа добавьте
`SABY_POINT_ID` и `SABY_PRICE_LIST_ID` и перезапустите `chainya-shop`.

## Т-Банк и CDEK

Шаблон новых параметров — `backend/integrations.env.example`, серверный файл —
`/etc/chainya-shop-integrations.env` с правами `0600`. Режимы по умолчанию:
`TBANK_CHECKOUT_MODE=off`, `CDEK_INTEGRATION_MODE=off` и
`SABY_ORDER_SYNC_MODE=off`.

Для локальной проверки поддерживается отдельный DEMO-терминал:
`TBANK_CHECKOUT_MODE=demo` разрешён только при `CHAINYA_TEST_MODE=1` и только
для ключа с суффиксом `DEMO`; Saby и CDEK при этом остаются заблокированы.
Боевой терминал работает только при `CHAINYA_TEST_MODE=0`,
`TBANK_CHECKOUT_MODE=auto` и полностью настроенном онлайн-чеке. Checkout
сохраняет `PaymentId`/`PaymentURL`, дедуплицирует повторный запрос по
`Idempotency-Key`, а оплатой считает только подписанный callback `CONFIRMED` на
`/api/payments/tbank/notification`. Страницы `/payment/success` и
`/payment/fail` сами статус не меняют.

Полный возврат тестового/боевого платежа доступен владельцу через
`POST /api/admin/orders/{id}/tbank/refund` и кнопку в панели. Повторный запрос
не создаёт второй возврат.

Онлайн-чек выключен до подтверждения СНО, ставок НДС и версии ФФД. После этого
задаются `TBANK_RECEIPT_*` и `TBANK_RECEIPT_ENABLED=1`; один и тот же серверный
чек передаётся в `Init` и полный `Cancel`. Боевой режим `auto` без настроенного
чека не включается.

Ключи CDEK API хранятся только в `/etc/chainya-shop-integrations.env`.
Публичная корзина ищет города и ПВЗ через сервер, а цену считает по тарифам
«Посылка склад-склад» (136) и «Посылка склад-дверь» (137). Вес определяется по
фасовкам в корзине плюс `CDEK_PACKAGING_WEIGHT_G`; габариты задаются
`CDEK_PACKAGE_*`. При создании заказа сервер повторяет расчёт и проверяет, что
ПВЗ действующий и относится к выбранному городу.

Расчёт и справочники не создают внешних сущностей. Регистрация оплаченного
отправления доступна отдельной кнопкой владельца только после установки
`CDEK_SHIPMENT_POINT`, отключения общего тестового режима и явного режима
`CDEK_INTEGRATION_MODE=manual`. В `off`/`shadow` создание отправлений
заблокировано независимо от наличия ключей.
