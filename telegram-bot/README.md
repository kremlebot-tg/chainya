# Бот чайной «Чайня»

Самодостаточный телеграм-бот: закрывает всю потребность **прямо в чате**, а не
просто ведёт на сайт. Кнопками можно выбрать чай, подобрать сорт по вкусу, взять
наугад, сохранить в избранное, забронировать стол и посмотреть, как нас найти.
Сайт и Telegram Mini App временно не показываются в интерфейсе бота: браузер
Telegram на iPhone блокирует домен предупреждением Apple. Сам бот остаётся
полностью рабочим в чате.

Работает через **long-polling**: не нужен ни вебхук, ни белый IP.

## Что умеет

- **🍵 Выбрать чай** — каталог по категориям (белый, зелёный, красный, улун,
  пуэр, особое). Карточка чая — это картинка с **вкусовым профилем, нарисованным
  на самом фото** (золотые полоски), плюс описание и цена по фасовкам 25/50/100 г.
- **🎯 Подобрать по вкусу** — выбираешь ноту (цветочный, фруктовый, медовый…),
  бот показывает сорта, где она звучит ярче всего.
- **🎲 Наугад** — случайный чай из наличия, если глаза разбегаются.
- **❤️ Избранное** — 🤍 на карточке сохраняет чай; список хранится между
  сессиями (`favs.json`).
- **📅 Забронировать стол** — пошагово кнопками (день → свободное время →
  формат → гости → подтверждение). Бот получает доступность из общего backend,
  сохраняет бронь в ту же базу, что и сайт, и не допускает пересечений
  двухчасовых сессий. Уведомление владельцу отправляет backend.
- **📍 Наш зал** — фото зала, адрес, часы, кнопка «на карте».
- Постоянная кнопка возле поля ввода открывает список команд, а не сайт.

## Данные и картинки

При запуске и затем каждые пять минут бот валидирует опубликованный
`https://chainya.ru/api/catalog` и атомарно обновляет названия, описания, цены,
наличие и список товаров из админ-панели. Если API недоступен или вернул
некорректный документ, бот продолжает работу с последней корректной копией.
`teas.json` остаётся аварийным fallback. Карточки и обложку бот рисует заранее,
используя шрифты и изображения из корня этого репозитория:

```bash
python build_data.py     # src.html сайта → резервный teas.json
python make_cards.py     # teas.json + media/teas/*.jpg → media/cards/<id>.jpg
python make_start.py     # обложка витрины → media/start.jpg
```

Рантайму нужны только `bot.py`, `teas.json` и папка `media/` (`cards/`, `teas/`,
`start.jpg`, `hall.jpg`). Генераторы — для разработки, на сервер их класть не нужно.

## Запуск

```bash
cd /Users/mac/Desktop/Чайня/site/telegram-bot
cp .env.example .env        # впишите BOT_TOKEN и при желании OWNER_CHAT_ID
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

`.env`:
- `BOT_TOKEN` — от @BotFather (секрет, не коммитится).
- `BOOKING_API_URL` — адрес общего backend, в production `https://chainya.ru`.
- `BOOKING_BOT_SECRET` — отдельный случайный секрет для создания броней. Одно
  и то же значение должно находиться в `.env` бота и окружении backend. Без него
  бот показывает безопасную ошибку и не создаёт неподтверждённую бронь.
- `OWNER_CHAT_ID` — кому слать прочие служебные сообщения. Можно несколько
  через запятую/пробел; уведомления об общих бронях отправляет backend.
  Свой id узнать командой `/id` в боте.

Создать общий секрет:

```bash
openssl rand -hex 32
```

Каждая новая и подтверждённая бронь занимает единственный стол на 120 минут.
Отменённая или завершённая бронь освобождает время. Если два гостя нажали
подтверждение одновременно, сервер принимает только первую заявку.

Production нужно обновлять согласованно: сначала сохранить один и тот же
`BOOKING_BOT_SECRET` в окружении backend и `/opt/chainya-bot/.env`, затем
обновить backend и код бота и перезапустить оба сервиса. До завершения обоих
шагов новая бронь через бот должна считаться недоступной, а не принятой.

## Круглосуточно (прод)

Держим на сервере под systemd. Юнит `/etc/systemd/system/chainya-bot.service`:

```ini
[Unit]
Description=Chainya Telegram bot
After=network.target

[Service]
User=chainya-bot
Group=chainya-bot
WorkingDirectory=/opt/chainya-bot
EnvironmentFile=/etc/chainya-bot.env
Environment=FAVS_PATH=/var/lib/chainya-bot/favs.json
ExecStart=/opt/chainya-bot/.venv/bin/python bot.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

Публикация выполняется из корня Git-репозитория атомарным скриптом
`deploy-bot.sh`: он тестирует код, создаёт отдельный release, сохраняет
`favs.json`, запускает процесс без root и при ошибке возвращает предыдущую версию.

Локальная проверка из чистого окружения:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt 'pytest>=9,<10'
.venv/bin/python -m pytest -q
```

Production-хост задаётся deploy-скриптом; рабочий каталог — `/opt/chainya-bot`.

## Команды

`/start` меню · `/menu` каталог · `/taste` подбор по вкусу · `/fav` избранное ·
`/book` бронь · `/contacts` адрес · `/site` сообщение о временном отключении
веб-приложения · `/id` свой chat_id.
